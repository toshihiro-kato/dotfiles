- 各回答は必ず次の形式で出力すること
- 冒頭に「=== Claude ===」を1行で置く
- 末尾に「=== /Claude ===」を1行で置く
- 長文は見出し(##)を使って分割する
- コードブロックは必ず ``` で囲む（可能なら言語名も付与）
- 箇条書きは `-` を使い、読みやすさを優先すること

## Git コミットルール
- git commit を実行する前に必ずユーザーに確認を取ること。勝手にコミットしない
- コミット対象のファイル一覧とコミットメッセージの案を提示し、承認を得てから実行する
- コミットの粒度やメッセージはユーザーのこだわりがあるため、自己判断で決めない

## コミットメッセージフォーマット
- Conventional Commits 形式に絵文字プレフィックスを付与する
- type と description は必須、body / footer は必要に応じて記載
- scope は使わない。`feat(walkthrough):` のような scope 付き形式は禁止

```
<emoji> <type>: <description>

[optional body]

[optional footer]
```

### type 一覧
| 絵文字 | type | 用途 |
|--------|------|------|
| 🧱 | build | ビルドシステムや外部依存の変更（例: パッケージのバージョンアップ） |
| 👾 | ci | CI設定ファイル・スクリプトの変更（例: GitHub Actionsの追加・変更） |
| 📚 | docs | ドキュメントのみの変更（例: README更新、ソースにコメント追加・変更） |
| ✨ | feat | 新機能の追加（例: 新しい機能を開発した） |
| 🐞 | fix | バグ修正（例: 不具合を修正した） |
| ⚡ | perf | パフォーマンス改善（例: SQLクエリのN+1問題を解消した） |
| ♻️ | refactor | バグ修正でも機能追加でもないコード変更（例: 関数名変更、処理の共通化） |
| 👗 | style | コードの意味に影響しない変更（例: インデントの修正、フォーマット） |
| ✅️ | test | テストの追加・修正（※新機能+テストは可能なら同じfeatコミットに含める） |
| 🚀 | release | リリース関連（例: コンテナイメージのタグ変更、自作gem/npmパッケージのバージョンアップ） |
| ⛏️ | chore | その他の雑務（例: gitignoreにファイル追加、githubテンプレの修正・追加・削除） |
